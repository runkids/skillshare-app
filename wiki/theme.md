# Theme and styling

How the app styles its own windows so they match the CLI UI it embeds, and how the theme stays in sync with that iframe. Load with `python3 scripts/ai-context.py theme`.

## Styling and theme

- Tailwind 4 via `@tailwindcss/vite`; no `tailwind.config`. `src/index.css` imports `tailwindcss` and `theme-tokens.css`, declares `@custom-variant dark` on the `.dark` class, and maps tokens to utilities in `@theme inline` (`bg-bg`, `bg-surface`, `text-ink`, `border-line`, `text-ink-2`, ...). Legacy aliases (`paper`, `pencil`, `muted`, `accent`, `danger`, ...) map onto the same tokens.
- Components mostly use arbitrary values on raw tokens, e.g. `bg-[var(--surface)]`, `rounded-[var(--r-box)]`, `shadow-[var(--sh-box)]`, `border-[length:var(--bw)]`. Prefer tokens over hex colors.
- `theme-tokens.css` defines four token sets: Clean light, Clean dark, Playful light, Playful dark. Style is `html[data-theme="playful"]` (absent means Clean); mode is the `dark` class on `html`. The token block is copied from the CLI's `ui/src/components.css` by `python3 scripts/sync-theme-tokens.py <path to skillshare>/ui/src/components.css`, so the app's windows match the dashboard; rerun it when the CLI changes its tokens, and do not edit the block by hand.
- `--edge` is the page edge the title bar and the settings sidebar sit on: `--shell` where the dashboard shows Clean's inset panel (Clean at 768px and wider, unless a custom theme sets `data-layout="full"`), otherwise `--side`. On the shell the title bar drops its bottom rule (`--edge-line`).
- `ThemeProvider` keeps two axes: `style` (`clean|playful|custom`, localStorage `skillshare-style`) and `modePreference` (`light|dark|system`, localStorage `skillshare-theme-preference`; migrates the legacy `skillshare-theme` key). `system` follows `prefers-color-scheme`. Changes briefly add `theme-transitioning` to `html`.
- Custom style: the theme is made in the CLI UI's theme editor (its `/appearance` page; Settings → Appearance links there once a theme exists). The app keeps the CLI UI's report in localStorage `skillshare-custom-theme` (`src/context/customTheme.ts`): the theme JSON, to hand back, and the custom properties the CLI UI derived for each mode. It sets the current mode's properties inline on `html`, with `data-theme="playful"` for a Playful base and `data-layout="full"` for a Clean base without the inset panel, and removes them when the style or mode changes. Only the token names a custom theme owns are taken, and values must be colours, lengths, borders or font stacks (no function but `rgba()` and `var()`). The app does not load the theme's web font, so its own windows use an installed copy or the system font. Custom falls back to Clean when the saved theme is missing or invalid; `index.html` paints the saved background before React loads.
- Iframe sync in `CliWebView`: the initial URL carries `?theme=` (`playful`, `dark` or `clean`, all an older CLI UI reads; a custom theme maps to its base style) plus `mode` and `style`, which a newer CLI UI uses to start with both axes right, and, once a custom theme is saved, `custom-theme` (base64url of the theme JSON; sent under any style, so the CLI UI's editor opens on the saved theme instead of its default). After load, and on every change made in the app, it posts `{ type: 'theme-push', mode, style }` (plus `custom` for Custom) to the iframe. A change the CLI UI reported is not pushed back: while the user drags a colour picker, an echo of an earlier report would undo the newer colour. It accepts `{ type: 'theme-change', theme }` messages only from the current iframe; `playful`/`clean` set style, `dark`/`light` set mode, and `custom` (with `custom` and `vars`) saves and applies the custom theme. A report of the saved theme with different `vars` updates only the colours, since a newer CLI can derive them differently. Reports that arrive before the iframe's `load` event or within 2 s after any load or `{ type: 'theme-init' }` message (`STARTUP_REPORT_MS`; a newer CLI UI posts `theme-init` at each page start) describe how the CLI UI started, not a user choice: a differing one is answered with another `theme-push` and never saved, because `?theme=` cannot carry Dark + Clean or Playful dark and WebKitGTK does not keep the iframe's `localStorage` (issue #128).
- Language sync in `CliWebView`: the CLI UI posts `{ type: 'locale-change', locale }` when the user picks a language (runkids/skillshare#981). The shell accepts it only from the current iframe and only when `locale` looks like a language tag, saves it as `skillshare-app:cli-locale` in its own localStorage, and sets `?lang=` on every later iframe URL, overriding any `lang` in a reopened route. WebKit drops the cross-origin iframe's storage between launches, so the CLI UI otherwise reopens in the system language (runkids/skillshare#982). An older CLI UI ignores `?lang=`.
